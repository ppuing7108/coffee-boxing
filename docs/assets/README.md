# 복싱 게임 리소스

2026-10-15 리소스 규격에 맞춘 2D 카툰 에셋. 실행용 파일은 `public/assets/`에 있다.

| 구성 | 파일 수 |
| --- | ---: |
| 복서 4종 × 홍/청 × 동작 10종 | 80 PNG |
| 상반신 초상화 | 8 PNG |
| 타격 / 크리티컬 / 방어 / 바람 이펙트 | 4 PNG |
| 링 / KO / FIGHT / 커피 / 코너 장식 | 6 PNG |
| 로딩 규격 | manifest.json |

## 실행

프로젝트 루트에서 Node.js 22 이상으로 실행한다. npm 패키지 설치는 필요 없다.

```sh
node scripts/check-assets.js
node --test test/check-assets.test.mjs
```

다른 납품 폴더를 검사할 때는 `node scripts/check-assets.js /path/to/assets`를 사용한다. 실패하면 종료 코드 1과 파일별 사유를 출력한다.

## 체크리스트

- [x] 동작 시트 80개, 초상화 8개, 이펙트 4개, UI 6개 존재
- [x] 선수 동작 프레임 원본 512×512, 화면 표시 256×256, 가로 한 줄, 프레임 간 여백 없음
- [x] 모든 시트의 픽셀 크기와 프레임 수가 manifest 및 규격과 일치
- [x] RGBA PNG. 캐릭터·이펙트·UI 장식은 실제 알파 투명도 포함
- [x] 링은 장면 전체를 그린 불투명 RGBA 배경
- [x] 12 fps, 반복·마지막 유지·impactFrame 메타데이터 일치
- [x] 각 프레임이 비어 있지 않으며 프레임 가장자리에 닿지 않음
- [x] 동작 프레임 바닥이 원본 y=480에 정렬됨 (래스터 보간 허용 오차 2px)
- [x] 홍→청 변환은 지정된 두 RGB 색만 변경하며 알파와 다른 픽셀은 동일
- [x] 공격과 회피 마지막 프레임이 해당 선수의 idle 첫 프레임과 픽셀 단위로 동일
- [x] CRC 및 압축 데이터 검증으로 PNG 손상 검사

발의 가로 중심, 오른쪽을 보는 자세, 펀치 타격 자세, 루프의 자연스러움은 PNG 크기만으로 판정할 수 없다. 원화와 동작별 컨택트 시트를 육안 확인했으며, 실제 재생은 [preview.html](preview.html)에서 추가 확인할 수 있다. 자동 검사 결과를 이러한 의미적 항목의 합격으로 해석하지 않는다.

## 미리보기와 게임 연결

[preview.html](preview.html)을 브라우저로 열면 네 선수와 두 코너의 동작, 초상화, 이펙트, UI를 확인할 수 있다. 선수·코너 선택, 좌우 반전, 기준점 표시, 일시정지, 프레임 탐색 기능이 있다. 외부 라이브러리나 서버가 필요 없다. 현재 환경에서는 브라우저 자동 재생 검증은 수행하지 않았다.

게임은 `manifest.frameSize=512`로 원본을 잘라 `displayFrameSize=256`으로 그린다. 기존 선수 표시 배율, 링 1280×720, 화면 기준점 `(128,240)`은 유지한다. 원본 기준점은 `(256,480)`이다. 초상화·이펙트·UI의 해상도는 기존 규격을 유지한다. `block`과 `ko`는 마지막 프레임을 유지한다. `impactFrame`은 0부터 시작한다. 일부 중간 포즈는 재사용하므로 모든 프레임이 고유한 원화는 아니다.

512 출력은 보관된 원화에서 직접 다시 래스터화한다. 이미 완성된 256 PNG를 확대하지 않는다. 다만 원화 자체가 작은 A/B는 추가 디테일을 복원하지 못하므로, 512 파일만으로 선명도가 두 배가 된다는 뜻은 아니다. C/D의 새 원화도 일부 확대 보간을 포함한다.

## 원본과 재생성

fighter-b는 애니메이션에 맞춰 긴 검은 포니테일과 갈색 피부의 여성 복서로 프로필을 통일했다. 전용 원화는 `sources/portrait-b-female.png`이며, 프로필 두 장만 다시 만들려면 `node scripts/build-assets.mjs --portrait-b-only`를 실행한다.

`sources/portraits-legacy.png`는 최초 제작 당시의 네 선수 원본 묶음이다. A/C/D의 원화로 사용하며, 오른쪽 위의 이전 남성 B 그림은 재생성 시 건너뛴다. 게임은 이 묶음을 직접 읽지 않고 `public/assets/fighters/{skin}/{corner}/portrait.png`를 읽는다.

원화는 내장 `image_gen` 도구로 생성했다. 실제 전달한 프롬프트는 [prompts.json](prompts.json)에, 원본 PNG는 [sources/](sources/)에 보관했다. API 키를 사용하지 않았다.

```sh
node scripts/build-assets.mjs
node scripts/check-assets.js
```

재생성 스크립트는 보관된 원화의 프레임 영역을 분리하고, 작은 잔여물을 제거하며, 기준점과 크기를 맞추고, 의상 팔레트를 확정한 다음 홍/청 시트를 만든다. PNG 인코딩과 알파 보간도 Node.js로 처리한다. 생성된 `public/assets/` 파일을 덮어쓰므로 수동 수정한 리소스가 있다면 먼저 보관한다. AI 원화 재생성 호출이나 네트워크 연결 없이 동일한 결과물을 다시 만들 수 있다.

사운드는 규격의 선택 항목으로 이번 납품에 포함하지 않았다.


## 프레임 일관성 검토

C/D는 기존 idle0을 이미지 생성 참조로 삼아 동작 모델 시트와 KO 시트를 다시 제작했다. 각 원화 시트의 guard에서 정한 단일 축척을 모든 포즈에 공통 적용한다. 원래 idle 참조는 보존하며, 런타임 idle은 새 모델 시트의 guard로 통일한다. C의 긴 잽, D의 머리 크기가 달라진 피격·승리 포즈는 제외하고 같은 시트의 대체 포즈를 사용한다. 등에 돌아선 포즈나 타격 섬광을 추가하지 않았다.

```sh
node scripts/build-assets.mjs
node scripts/annotate-heads.mjs
node scripts/check-assets.js --report=docs/assets/consistency-report.json
node --test test/asset-metrics.test.mjs test/check-assets.test.mjs test/sprites.test.mjs
```

머리 영역과 검토 이미지는 `head-regions.json`, `head-overrides.json`, `review/*-heads.png`에 있다. 초록 사각형은 기울어진 머리 영역이다. 영역 추적은 제안 도구이며, 가려진 머리나 원화 자체의 크기 차이는 자동으로 해결되지 않는다. 최종 수치와 실패 목록은 `consistency-report.json`을 확인한다. 기존 A/B의 머리 폭 위반은 숨기지 않으며, 전체 검사 종료 코드가 1이면 아직 전체 납품 합격이 아니다.


512 원본 기준 최종 검토 (홍코너 56프레임, 청코너 동일):

| 선수 | 몸 면적 실패 | 머리 폭 실패 |
| --- | ---: | ---: |
| A | 2 | 13 |
| B | 0 | 21 |
| C | 0 | 0 |
| D | 0 | 8 |

D는 KO 3·4번과 victory 0~5번에서 머리 폭이 약 1.088~1.099배다. A는 victory 1·5번 몸 면적이 0.879배로 하한 0.88에 미달한다. 머리 추적용 256 축소 미리보기에서 통과했던 경계 프레임도, 최종 판정은 512 원본 알파 픽셀에서 수행하므로 실패할 수 있다. 허용치를 넓히거나 프레임별 확대·축소로 통과시키지 않았다. **전체 일관성 검사는 미통과 상태이며 추가 원화 수정이 필요하다.**

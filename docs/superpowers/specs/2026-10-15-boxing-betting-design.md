# 복싱 베팅 게임 설계

- 작성일: 2026-10-15
- 목적: 커피호명기(https://ppuing7108.github.io/coffee/)보다 재밌는 "커피 살 사람 뽑기" 멀티플레이 게임
- 리소스 규격: [2026-10-15-boxing-assets-spec.md](./2026-10-15-boxing-assets-spec.md) (Codex 작업용)

## 1. 개요

여러 명이 각자 기기로 같은 방에 접속한다. 매 스테이지마다 남은 참가자가 홍/청 코너에 베팅하고, AI 복서 둘이 자동으로 싸운다. **진 선수에 건 사람들이 다음 스테이지로 진출**하며, 진 쪽 베팅자가 1명이면 그 사람이 최종 패배자(커피 구매)다.

용어: "스테이지" = 베팅 1회 + 경기 1회. (복싱의 3분 라운드가 아님)

## 2. 결정 사항 요약

| 항목 | 결정 |
|---|---|
| 백엔드 | Node.js + Express(정적 파일) + Socket.IO, 로컬 실행 (`http://<IP>:3000`) |
| 상태 저장 | 서버 메모리 (재시작 시 방 소멸) |
| 프론트 | Vanilla JS(ES 모듈, 빌드 없음) + CSS 스프라이트 애니메이션 |
| 판정 권한 | 서버가 모든 판정 (베팅 선착순, 전투 결과) |
| 경기 길이 | 7~30초 (KO 연출 제외) |
| 공정성 | 두 선수 능력치·기술 확률 완전 동일, 외형만 랜덤 |
| 베팅 미선택 | 15초 제한 + 시간 종료 시 자동 배정, 방장 "바로 진행" 가능 |
| 베팅 변경 | 불가 (한 번 누르면 확정) |
| 코너 상한 | 올림(생존자 수 / 2) |

## 3. 게임 흐름

```
LOBBY ──(방장 시작, 2명 이상)──▶ BETTING ──(전원 선택 / 15초 / 방장 '바로 진행')──▶ FIGHTING
  ▲                                ▲                                                  │
  │                                └──────────(진 쪽 베팅자 2명 이상)─────────────────┤
  └────────(방장 '다시하기')──── FINISHED ◀──(진 쪽 베팅자 1명 = 최종 패배자)──────────┘
```

### 3.1 로비
- 첫 화면에서 닉네임 입력 → "방 만들기"(4자리 영숫자 코드 발급) 또는 "코드로 입장".
- 방 안에서 닉네임 중복 불가.
- 방을 만든 사람이 방장. LOBBY 상태에서만 입장 가능, 게임 시작 후에는 신규 입장 거절(`GAME_IN_PROGRESS`).
- 방장은 참가자 2명 이상일 때 시작 가능. 시작 순간 로비에서 접속이 끊겨 있던 사람은 참가자에서 빠진다.

### 3.2 베팅 (BETTING)
- 참가 대상: 현재 스테이지 생존자(active). 관전자(이전 스테이지에서 이긴 쪽에 건 사람)는 베팅 불가, 화면만 봄.
- **한쪽 상한 = 올림(생존자 수 / 2).** 예: 2명 1:1, 3명 2자리씩, 5명 3자리씩 → 실제 배분은 최소 3:2처럼 반반에 가깝게 갈린다. 서버는 이벤트를 하나씩 순서대로 처리하므로 먼저 도착한 요청이 자리를 차지한다. 꽉 찬 쪽 요청은 `SIDE_FULL`로 거절되고, 클라이언트는 그쪽 버튼을 비활성화한다.
  - 예: 3명 모두 홍 클릭 → 먼저 도착한 2명만 홍, 1명은 거절되어 청만 선택 가능.
  - 상한 덕분에 양쪽은 항상 내림(생존자 수 / 2)명 이상이고, 다음 스테이지 인원은 최대 올림(n/2)명이라 매 스테이지 절반 가까이 줄어든다.
- 한 번 베팅하면 변경 불가(`ALREADY_BET`).
- 종료 조건 (먼저 오는 것):
  1. 생존자 전원 베팅 완료
  2. 15초 마감(`deadline`)
  3. 방장 `bet:closeNow`
- 2·3의 경우 미선택자를 자리가 남은 쪽에 랜덤 배정. 상한 규칙 덕분에 양쪽 최소 1명이 보장된다.
- 접속이 끊긴 생존자도 참가자로 남고 동일하게 자동 배정된다. (나가서 커피 회피 불가)

### 3.3 경기 (FIGHTING)
- 서버가 시드로 경기 대본을 미리 계산해 방송 → 모든 클라이언트가 같은 타이밍에 재생 (4장 참고).
- 서버는 `경기 길이 + KO 연출 3초 + 결과 표시 3초` 후 결과 확정.

### 3.4 결과 판정
- 패배 코너에 베팅한 사람들 = 다음 생존자.
  - 2명 이상 → 다음 스테이지 BETTING
  - 1명 → FINISHED, 그 사람이 최종 패배자 ☕
- 승리 코너에 베팅한 사람들 → 관전자.
- 상한이 올림(n/2) < n (n ≥ 2)이므로 매 스테이지 인원이 줄고, 2명 남으면 반드시 1:1로 갈라지므로 게임은 항상 종료된다.

### 3.5 종료 / 다시하기
- FINISHED 화면: 최종 패배자 크게 표시 + 스테이지별 기록.
- 방장 `game:restart` → 같은 멤버로 LOBBY 복귀(신규 입장 다시 허용).

### 3.6 접속 / 재접속 / 방장
- 입장 시 서버가 `token`(랜덤 UUID) 발급 → localStorage `{code, token}` 저장.
- 새로고침/재접속 시 `room:rejoin`으로 같은 참가자 복귀. 경기 중이면 경과 시간부터 이어서 재생.
- LOBBY에서 접속 끊긴 참가자는 60초 후 제거. 게임 시작 후에는 제거하지 않음.
- 방장 접속이 끊기면 접속 중인 사람 중 가장 먼저 입장한 사람에게 방장 권한 이전 (LOBBY·게임 중 모두 동일). 원래 방장이 재접속해도 권한은 되돌리지 않음.
- 방장이 아닌 참가자의 접속 끊김은 진행에 영향 없음 (베팅은 자동 배정, 최종 패배자 판정도 그대로 적용).
- 모든 참가자 접속이 끊긴 지 10분 지나면 방 삭제.

## 4. 전투 시스템

### 4.1 기본
- 체력 각 100. 한 번의 주고받기(exchange)마다 두 선수가 기술 5개 중 하나를 동시에 선택.
- 기술 선택 확률: 각 20%, 양쪽 동일.

### 4.2 상성표 (행 = 내 기술, 열 = 상대 기술, 값 = 상대에게 주는 데미지)

| 나 \ 상대 | 잽 | 훅 | 어퍼컷 | 막기 | 피하기 |
|---|---|---|---|---|---|
| **잽** | 6 (서로 맞음) | 6 (먼저 꽂힘) | 0 | 0 (막힘) | 6 (빨라서 맞힘) |
| **훅** | 0 | 12 (서로 맞음) | 12 (먼저 꽂힘) | 3 (막힘) | 0 |
| **어퍼컷** | 20 (파고듦) | 0 | 20 (서로 맞음) | 20 (가드 뚫음) | 0 |
| **막기** | – | – | – | 0 (대치) | 0 (대치) |
| **피하기** | – | 반격 6 | 반격 6 | 0 (대치) | 0 (대치) |

- 공격 간 상성: 잽 > 훅 > 어퍼컷 > 잽.
- 막기: 잽·훅 방어, 어퍼컷에 뚫림. 피하기: 훅·어퍼컷 회피+반격, 잽에 맞음.
- 변수: 데미지 ±20% 랜덤, 10% 크리티컬 ×1.5. 정수로 반올림. 양쪽 동일 적용.
- 위 수치는 시작값. 구현 시 시뮬레이션으로 평균 경기 시간 ~15초가 되도록 조정.

### 4.3 시간 (클라이언트 연출과 일치해야 함)
- exchange 길이는 결과 유형별 고정값 (예: 대치 0.8초, 일반 타격 1.0초, 크리티컬/어퍼컷 1.2초). 값은 리소스 규격의 애니메이션 길이와 맞춘다.
- 경기 길이 = exchange 길이 합 (첫 exchange 시작 ~ KO 타격 순간).

### 4.4 대본 생성과 7~30초 보장
1. `simulate(seed)` → KO까지 exchange 목록 생성 (같은 시드 = 같은 결과).
2. 총 길이가 7~30초를 벗어나면 seed+1, seed+2 … 로 재생성 (최대 50회, 모두 벗어나면 범위에 가장 가까운 대본 사용 — 시뮬레이션상 범위 밖은 약 1%라 사실상 발생하지 않음).
3. 서버 방송: `fight:script { startAt, fighters, script }`. `startAt` = 서버시각 + 1.5초(로딩 여유).
4. 클라이언트는 서버 시각 오프셋(접속 시 `time:sync`로 측정)을 보정해 `startAt`부터 재생.

```js
// exchange
{ t: 3.2, dur: 1.0,
  red: 'HOOK', blue: 'DODGE',
  result: 'BLUE_COUNTER',            // RED_HIT | BLUE_HIT | TRADE | BLOCKED | COUNTER... | STANDOFF
  dmg: { red: 6, blue: 0 },          // 이번에 각자 받은 데미지
  hp:  { red: 74, blue: 88 },        // 적용 후 체력
  crit: false, ko: null }            // 마지막 exchange는 ko: 'red' | 'blue'
```

> 대본을 한 번에 보내므로 개발자도구로 결과를 미리 볼 수 있지만, 베팅이 이미 잠긴 뒤라 영향 없음.

### 4.5 선수 외형
- 스킨 4종 중 2개를 랜덤으로 뽑아 홍/청에 배정 (같은 스킨 가능, 코너 색으로 구분). 베팅 카드에 보여야 하므로 **베팅 시작 시** 정한다.
- 선수 이름: 이름 풀(예: "강펀치 김씨", "모래주먹 박씨" …)에서 랜덤. 능력치 표시 없음.

## 5. 통신 이벤트 (Socket.IO)

상태가 바뀔 때마다 서버가 방 전체 상태 `room:state`를 방송하고 클라이언트는 그대로 렌더링한다.

| 방향 | 이벤트 | 페이로드 / 응답(ack) |
|---|---|---|
| C→S | `room:create` | `{nickname}` → `{ok, code, token}` |
| C→S | `room:join` | `{code, nickname}` → `{ok, token}` / `ROOM_NOT_FOUND`, `NICKNAME_TAKEN`, `GAME_IN_PROGRESS` |
| C→S | `room:rejoin` | `{code, token}` → `{ok}` / `INVALID_TOKEN` |
| C→S | `time:sync` | `{}` → `{serverNow}` |
| C→S | `game:start` | 방장 전용, 2명 이상 → `{ok}` / `NOT_HOST`, `NOT_ENOUGH_PLAYERS` |
| C→S | `bet:place` | `{side}` → `{ok}` / `SIDE_FULL`, `ALREADY_BET`, `NOT_ACTIVE`, `NOT_BETTING_PHASE` |
| C→S | `bet:closeNow` | 방장 전용 |
| C→S | `game:restart` | 방장 전용, FINISHED에서만 |
| S→C | `room:state` | 아래 참고 |
| S→C | `fight:script` | `{startAt, fighters:{red:{skin,name}, blue:{skin,name}}, script[]}` |

```js
// room:state
{ code, phase: 'LOBBY'|'BETTING'|'FIGHTING'|'FINISHED',
  hostId, stage: 2,
  players: [{ id, nickname, connected, status: 'active'|'spectator', joinedAt }],
  bets: { red: [playerId...], blue: [playerId...] },
  cap: 2,                      // 한쪽 상한
  deadline: 1760500000000,     // 베팅 마감(서버 시각 ms)
  history: [{ stage, winner: 'red', bets: {...} }],
  loser: null }                // FINISHED 시 최종 패배자 id
```

## 6. 구조

```
server/
  index.js        Express 정적 서빙 + Socket.IO 연결, 이벤트 → room 메서드 호출
  rooms.js        방 생성/조회/삭제, 코드 발급
  room.js         상태 흐름(phase 전환), 참가자/방장/재접속 — 소켓 코드 없음
  betting.js      placeBet, autoAssign, cap 계산 — 순수 함수
  fight.js        simulate(seed), 상성표, 길이 보장 — 순수 함수
  rng.js          시드 기반 난수 (mulberry32 등)
public/
  index.html, style.css
  main.js         소켓 연결, room:state 수신 → 화면 전환
  lobby.js        닉네임/방 만들기/입장 화면
  betting.js      베팅 화면 (타이머, 버튼 비활성화)
  fight-player.js 대본 재생 (시간 동기화, HP바, 이펙트)
  sprites.js      manifest 로드, 스프라이트 시트 애니메이션
  assets/         리소스 (규격 문서 참고)
test/
  betting.test.js, room.test.js, fight.test.js   (node:test)
```

- `room.js` / `betting.js` / `fight.js`는 시간(`now`)과 난수를 인자로 받아 테스트에서 고정할 수 있게 한다.
- 타이머(베팅 마감, 경기 종료 대기)는 `index.js`/`rooms.js`에서 `setTimeout`으로 걸고 `room` 메서드를 호출한다.

## 7. 화면

1. **입장**: 닉네임 입력, 방 만들기 / 코드 입력 후 입장
2. **로비**: 방 코드(크게), 참가자 목록(방장 👑, 연결 상태), 방장에게만 "시작" 버튼
3. **베팅**: 홍/청 선수 카드(이름, 외형), 양쪽 베팅자 목록 실시간, 남은 시간, 상한 도달 시 버튼 비활성화 + "가득 참", 방장 "바로 진행"
4. **경기**: 링 배경, 양 선수 스프라이트, 상단 HP바 2개, 기술명/데미지 텍스트, KO 연출. 내가 건 코너 표시
5. **스테이지 결과**: 승리 코너, 다음 진출자 / 관전자 표시 → 자동으로 다음 베팅
6. **종료**: 최종 패배자 "☕ ○○○ 커피 사와라", 스테이지 기록, 방장 "다시하기"

## 8. 테스트

자동 (`node --test`):
- 베팅: 3명이 모두 홍 → 앞 2명만 수락, 3번째 `SIDE_FULL` / 5명 중 4번째 홍 `SIDE_FULL` / 중복 베팅 거절 / 관전자 베팅 거절 / 자동 배정 후 양쪽 ≥1 / 전원 베팅 시 즉시 FIGHTING
- 스테이지: 진 쪽 1명 → FINISHED·loser 지정 / 2명 이상 → 다음 BETTING, 이긴 쪽 spectator 전환 / 2명 남으면 반드시 1:1
- 전투: 시드 10,000개 전부 7~30초 / 홍 승률 50% ±2% / 같은 시드 같은 결과 / hp 음수 없음, 마지막 exchange에만 ko
- 방: 시작 후 입장 거절 / 방장 이탈 시 권한 이전 / 재접속 토큰 복귀

수동: 브라우저 탭 3~4개(일부 시크릿 창)로 동시 클릭, 새로고침, 탭 닫기 시나리오.

- 채팅, 사운드(리소스 규격에 선택 항목으로만 둠)
